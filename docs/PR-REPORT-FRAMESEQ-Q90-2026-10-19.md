# 桌宠动画缓存Q90清晰度提升

## 一、核心特性

所有动画缓存由Q70升到Q90，640×360源尺寸、24fps和白底反解white-v5保持一致。目的为减少二次有损量化，不把像素放大当作新增细节。全部106段从原始WebM重新解码，禁止从已损失细节的Q70缓存转码。旧运行包在新包验收前保留。

此前alpha底板清理约束见[反解v5报告](PR-REPORT-FRAMESEQ-ALPHA-FLOOR-2026-10-16.md)；本次只更换RGB编码质量，镂空还原仍挂起、erode仍为1、alpha无损。

## 二、修改文件说明

- pet/frameseq_provision.py：当前encoder串和WEBP_QUALITY改为Q90，Q70-v5进入历史档识别。默认转换与运行时采纳共用该档，自动拒绝旧缓存。
- scripts/check_frameseq_bundle.py：同步构建门，禁止把Q70缓存装进Q90包。
- pet/library.py：更新当前编码档的接口文档。
- tools/convert_frameseq.py：修正过期的分目录Q80说明，明确统一Q90及范围。
- tests/test_frameseq_provision.py：编码参数冻结和库级Q70-v5拒绝/同路径Q90采纳。
- tests/test_frameseq_bundle_gate.py：构建期也拒绝旧Q70-v5，保留新旧档对照诊断。
- docs/INDEX.md与本报告：记录换档依据、质量、体积、生成和运行结果。

## 三、实现要点

encoder从libwebp lossy q70 (bgra straight, unblend-white-v5)改为libwebp lossy q90 (bgra straight, unblend-white-v5)。UNBLEND_MARK仍是white-v5，不伪造源摘要，不创建另一套质量配置或运行时分支。既有缓存键包含实现与档位，自动失效；旧档回退WebM后由原有供给重生成，发布仍经临时目录和原子重命名。新生成树与正在运行的旧包为不同路径，不修改正在播放的帧。

## 四、性能分析

环境：macOS arm64、Python3.11、现有Pillow/libwebp，quality=70/90，method=4；从真实源解码首帧并经同一unblend_v3处理，比较alpha>0像素RGB相对反解后未压缩帧的PSNR。该指标衡量缓存追加的压缩误差，不能证明对未提供的高清原图有新增细节。

原完整缓存375429556字节、106段、25423帧。样本Q90帧体积约增加44%；本轮106段/25423帧全部转换成功，离线4进程耗时551.542秒。帧文件375403616→548345284字节（约+46.1%，不含meta），生成过程中没有失败段。转换阶段沿用原解码/反解/编码路径；本次离线4个低优先级进程并行，非应用新增线程。稳态不新增网络、周期任务或系统调用。实测旧包Q70与新Q90的待机/拖拽/移动首帧，Pillow内存解码各3轮×100次：Q70中位0.8368/0.8871/0.8455ms，Q90为1.0323/1.0580/1.0722ms，每帧增加0.17–0.23ms（约19%–27%）。这是单帧解码微基准，不是完整GUI性能或所有素材的上界。已有CPU/GPU帧缓存容量与渲染几何不变；长期内存行为未压测。

## 六、部署与验证边界

新包位于outputs/dsh-pet-q90，旧Q70运行包保留作回退。未改用户配置、缩放尺寸或宠物数量。验证覆盖源解码、缓存质量、全部帧alpha一致性、元数据采纳、包内资源、签名和真实进程启动；桌面透明合成窗此前无法被自动截图工具可靠捕获，尚未对“肉眼更锐利”做盲测，也没有整机长期性能基准。未把单帧指标说成新增分辨率或恢复原素材中不存在的细节。
